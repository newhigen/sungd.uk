루트 되찾기

sungd.uk 아래 사이트 넷을 다시 짜는 계획 — 2026-08-07

2026-08-07 시점의 계획이다. 지금 상태와 다르다.

세운 뒤에 전제가 세 번 바뀌었다 — 호스팅이 Netlify 가 아니라 GitHub Pages 였고, today.sungd.uk 는 ai.sungd.uk 로 되돌렸고, 넘김(리다이렉트)은 안 걸기로 했다. 결정 과정 기록으로 두는 문서라 그때 그대로 둔다.

지금 상태는 각 repo 의 README · 무슨 일이 있었는지는 log.md · 실제로 쓰는 것은 cloudflare.md(넘김 조건식)와 status.sh(점검)

사이트는 아직 하나도 안 바뀌었다. 코드 작업은 끝나서 세 repo 브랜치에 올려뒀고, 남은 건 DNS 레코드·GitHub Pages 설정·Cloudflare 규칙이다. 웹에서만 되는 일이라 직접 해야 한다. 아래 순서대로 하면 각 단계가 끝나는 즉시 그 부분이 살아난다.

왜 바꾸나

사이트가 넷인데 서로 관계가 안 보인다. 루트 주소를 에세이 블로그가 쓰고 있어서 나머지가 형제인지 자식인지 애매하고, 어디에도 서로를 가리키는 동선이 없다. 한 사이트에 들어온 사람이 나머지를 못 본다.

tech 는 넉 달째 멈춰 있었다. 다만 세어보니 프로젝트 소개 14개가 이력서 근거로 쓸 자산이라 내리는 대신 해체해서 나눠 붙이기로 했다. 멈춘 사이트를 억지로 살리는 대신 안 멈춘 곳에 얹는 것이다.

루트는 링크트리로 안 만든다. 가장 좋은 주소를 체류 0초짜리 중계 페이지에 쓰는 셈이라, 소개와 프로젝트가 실린 그 자체로 목적지인 홈으로 간다.

최종 모양

sungd.uk          나 — 소개 + 프로젝트 14개
├── resume.       이력서
├── writing.      글 — 책·생각·기술

tech.sungd.uk 는 없어진다. 프로젝트 소개 14개는 루트에 남고, 기술 글 12편은 writing 으로 갔다. ai.sungd.uk 는 today 로 이름을 바꾼다 — ai 는 범위가 너무 넓은데 실제로 하는 일은 하나라서. 호스팅은 넷 다 GitHub Pages 그대로 두고, 옛 주소를 넘기는 일만 Cloudflare 가 맡는다.

끝난 것 — 코드

세 repo 모두 브랜치를 push 해뒀다. main 에는 안 합쳤다. 합치는 순간 배포가 돌아서 순서를 맞춰야 하기 때문이다.

repo브랜치한 일
blog-tech worktree-reorg-plan blog 걷어내고 루트 사이트로 개조, 홈을 소개+프로젝트+사이트 링크로 다시 씀, CNAME 을 sungd.uk 로
blog-writing reorg-writing 기술 글 12편 흡수, 기술 카테고리·필터·아이콘 추가, 도메인 표기 변경
ai-pick reorg-today CNAME·sitemap·robots·README 를 today.sungd.uk 로
검증한 것 — 두 Astro 사이트 모두 빌드 통과. writing 은 글 79편이 다 생성되고, 옮겨온 12편의 주소가 예전 그대로다(/claude-code-tips/ 등). 루트는 18쪽이 나오고 내부 링크에 깨진 곳이 없다.

남은 순서

순서를 지켜야 도메인이 겹치지 않는다. 각 단계 오른쪽에 그 단계가 끝나면 살아나는 것을 적었다.

1

writing 먼저

글 사이트가 새 주소로
  1. Cloudflare 에 writing.sungd.uk CNAME → newhigen.github.io 추가, 회색 구름
  2. cd ~/dev/blog-writing && git merge reorg-writing && git push
  3. blog-writing Settings → Pages → 커스텀 도메인을 sungd.uk 에서 writing.sungd.uk 로
  4. 인증서 발급되고 열리는지 확인

이 시점에 sungd.uk 는 주인이 없어져 잠깐 안 뜬다. 3단계까지 이어서 가면 된다.

2

today

ai 가 여기서 끊김
  1. Cloudflare 에 today.sungd.uk CNAME → newhigen.github.io 추가, 회색 구름
  2. cd ~/dev/ai-pick && git merge reorg-today && git push
  3. ai-pick Settings → Pages → 커스텀 도메인을 today.sungd.uk 로
  4. 열리는지 확인

GitHub Pages 는 repo 하나에 도메인 하나뿐이라 ai 와 today 를 같이 못 쓴다. ai.sungd.uk 는 여기서 끊기고 4단계에서 되살아난다.

3

루트 사이트

소개+프로젝트 홈이 뜸
  1. cd ~/dev/newhigen.github.io && git merge worktree-reorg-plan && git push — 워크플로가 Pages 로 배포한다
  2. blog-tech Settings → Pages → 커스텀 도메인을 tech.sungd.uk 에서 sungd.uk 로
  3. 인증서 발급되고 "Enforce HTTPS" 켜지는 것 확인

apex 는 이미 GitHub Pages A 레코드를 갖고 있어서 DNS 는 안 건드려도 된다. 주인만 바뀐다.

4

Cloudflare 규칙 — 옛 주소 되살리기

옛 글·tech·ai 가 다 넘어감
  1. sungd.uk·tech·ai 를 주황 구름으로
  2. Rules → Redirect Rules 에 아래 다섯 개를 순서대로 넣는다
  3. 헤더로 확인 (맨 아래 확인 명령)

Cloudflare 규칙 다섯 개

전부 301(Permanent), 쿼리스트링 보존 켬. 위에서부터 순서대로 걸리므로 순서가 중요하다. 글 주소 79개를 나열하는 대신 조건을 뒤집었다 — 루트 사이트가 쓰는 경로가 아니면 옛 글로 본다.

1. 옛 글 주소 → writing 루트가 쓰는 경로 여덟 개만 빼고 전부

조건:

http.host eq "sungd.uk"
and not starts_with(http.request.uri.path, "/_astro/")
and not starts_with(http.request.uri.path, "/about")
and not starts_with(http.request.uri.path, "/dashboards/")
and not starts_with(http.request.uri.path, "/fonts/")
and not starts_with(http.request.uri.path, "/projects")
and not starts_with(http.request.uri.path, "/resume")
and not http.request.uri.path in {"/" "/favicon.ico" "/favicon.svg" "/robots.txt" "/sitemap-0.xml" "/sitemap-index.xml"}

넘길 곳 — Dynamic:

concat("https://writing.sungd.uk", http.request.uri.path)
2. tech 프로젝트 → 루트 /projects/* 를 그대로 옮김

조건:

http.host eq "tech.sungd.uk" and starts_with(http.request.uri.path, "/projects")

넘길 곳 — Dynamic:

걸려 넘어질 곳

인증서 발급 순서

GitHub 이 커스텀 도메인 인증서를 발급하려면 그 이름이 회색 구름이어야 한다. 회색으로 두고 도메인 붙이기 → 발급 확인 → 그때 주황으로 바꾼다. 먼저 주황으로 켜면 발급이 막힌다.

SSL 모드는 Full 이상

Flexible 로 두면 GitHub 이 HTTPS 로 다시 보내고 Cloudflare 가 다시 받아서 무한히 돈다. Full 또는 Full (strict) 로 둔다.

규칙은 주황 구름에만 걸린다

지금 네 도메인 전부 회색이라 요청이 Cloudflare 를 그냥 지나쳐 GitHub 으로 간다. 규칙을 넣어도 안 걸린다. 응답에 cf-ray 헤더가 보이면 주황이 켜진 것이다.

루트는 자기 404 를 못 갖는다

1번 규칙 때문에 모르는 주소는 writing 으로 가고 거기서 404 가 난다. 옛 주소가 전부 글이었으니 대개는 맞는 동작이다. 대신 루트에 새 최상위 경로를 만들면(예: /notes) 1번 규칙의 제외 목록에 추가해야 한다. 안 그러면 새 경로가 writing 으로 넘어간다.

확인

주황으로 바꾸고 몇 분 기다렸다가 헤더만 받아본다.

curl -sSI https://sungd.uk/the-go-giver-1/            | grep -iE "^(HTTP|location|cf-ray)"
curl -sSI https://tech.sungd.uk/claude-code-tips      | grep -iE "^(HTTP|location)"
curl -sSI https://tech.sungd.uk/projects/claude-watch | grep -iE "^(HTTP|location)"
curl -sSI https://ai.sungd.uk/                        | grep -iE "^(HTTP|location)"
curl -sSI https://sungd.uk/projects                   | grep -iE "^(HTTP|location)"   # 넘어가면 안 됨

나중에

폴더·repo 이름 정리 사이트가 다 살아난 뒤에

폴더 이름 = 서브도메인 이름으로 맞추는 안. 지금은 규칙이 없다 — ai-pick 은 제품명, blog-writing 은 종류명, newhigen.github.io 는 GitHub Pages 흔적, resume 만 도메인과 같다.

newhigen.github.io → home       (repo: blog-tech → home)
blog-writing       → writing    (repo: blog-writing → writing)
ai-pick            → today      (repo: ai-pick → today)
resume             → 그대로
calc-tools         → 도메인 보류라 그대로

바꾸면 dev/CLAUDE.md, server-console 의 registry·문서, claude-config 스킬 2개의 경로도 같이 고쳐야 한다. 참고로 registry 는 지금도 없는 경로(sites/blog-tech)를 가리키고 있다.

Netlify·Pages 설정을 다시 잡는 중에 repo 이름까지 흔들면 어디서 틀어졌는지 못 찾는다. 그래서 사이트가 다 살아난 걸 확인한 뒤에 한다.

보류·미정 calc 도메인, package.json 이름, GA 태그
  • calc-tools — 도메인 안 붙임. 나중에 붙인다면 tools. 아래로 묶는 안이 있다.
  • package.json 이름이 아직 blog-tech 다.
  • Google Analytics 태그는 tech 시절 것을 그대로 쓴다. 사이트 성격이 바뀌었으니 나중에 볼 것.
  • blog-writing 의 Netlify 설정 — 어댑터와 netlify.toml 이 남아 있는데 실제 배포는 GitHub Pages 다. 안 쓰는 잔재라 이번엔 안 건드렸다.
