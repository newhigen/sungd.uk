# 재편 결정 기록

## 2026-08-07 — 구조·이름 결정

### 출발점

sungd.uk 아래 사이트 넷. 루트를 에세이 블로그가 쓰고 있어 tech·resume·ai 가 그 자식처럼 보이는데 실제론 형제다. 어디에도 서로를 가리키는 동선이 없어, 한 사이트에 들어온 사람이 나머지를 못 본다.

세어본 규모:

```
writing (sungd.uk)       글 67편 + 초고 17편        활발 (최근 커밋 06-12)
tech    (tech.sungd.uk)  기술 글 12편 + 프로젝트 14  마지막 글 04-04, 넉 달 멈춤
resume                   이력서 한 장
ai-pick                  큐레이션 페이지 하나 (매일 자동 갱신)
```

### 루트를 허브로, 단 링크트리는 안 만든다

루트는 가장 좋은 주소다. 링크만 있는 페이지를 올리면 체류 0초짜리 중계로 그 자리를 쓰는 셈이라, 소개와 프로젝트가 실린 "그 자체로 목적지인 홈"으로 간다.

허브보다 싸고 효과 큰 건 각 사이트 상단에 서로를 가리키는 링크 한 줄을 공통으로 넣는 것. 홈을 만들어도 이게 없으면 왕복이 안 된다.

### tech 는 내리지 않고 해체한다

"내용 없으니 내리자"가 처음 생각이었는데, 세어보니 프로젝트 소개 14개(career-radar·claude-watch·whooing-tools·worklog-dashboard 등)가 이력서 근거로 그대로 쓸 자산이었다. 내리면 그게 사라진다.

대신 멈춘 사이트를 억지로 살리지 않고 안 멈춘 곳에 얹기로 했다. 기술 글 12편은 writing 으로, 프로젝트는 루트로. 앞으로 기술 글을 써도 writing 한 군데만 굴리면 된다.

### 이력서는 루트에 안 올린다

루트 = 이력서면 "sungd.uk 보세요" 할 때마다 구직 신호로 읽히고 개인정보가 그냥 노출된다. 루트는 소개+프로젝트까지만, 이력서는 resume. 에 남긴다.

### 새 repo 를 안 만들고 newhigen.github.io 를 개조한다

루트 사이트에 필요한 것(프로젝트 콘텐츠, Astro 셋업)이 이미 그 repo 에 다 있다. 기술 글만 덜어내고 홈을 다시 쓰면 되므로 새로 만들 게 없다. 대신 Netlify 로 옮긴다 — GitHub Pages 는 301 리다이렉트를 못 걸어서, 옛 링크를 살리려면 Netlify 가 필요하다.

### ai. → today.

`ai` 는 너무 넓다. 주소만 보면 AI 관련 뭐든 있을 것 같은데 실제론 한 가지만 한다. 후보로 pick(고른다·repo 이름과 맞음), cc(Codex 도 다루는데 좁다), tools(큐레이션 성격이 안 산다), changelog(raw 목록 인상) 를 놓고 `today` 로 정했다. 매일 새벽 5시 20분 자동 갱신이고 첫 섹션이 "오늘 써볼 기능"이라 하는 일과 맞는다.

### 그 밖

- calc-tools 는 이번에 안 건드린다.
- 이 대화 도중 `~/dev/blog`, `~/dev/newhigen.github.io` 가 `~/dev/sites/` 밑으로 옮겨졌다(각각 blog-writing, newhigen.github.io). dev/CLAUDE.md 가 정한 컨벤션대로 자리를 잡은 것이고 내용은 그대로다. 이 문서의 경로는 옮긴 뒤 기준.

## 2026-08-07 — 실제로 작업하면서 바뀐 것

### 옛 글 주소는 `/posts/*` 가 아니었다

처음 계획에 리다이렉트를 `/posts/* → writing` 한 줄로 적었는데 틀렸다. writing 블로그는 글을 루트 바로 아래(`sungd.uk/the-go-giver-1/`)에 두고 있었다. 규칙 한 줄로는 못 덮으므로 글 79편의 주소를 하나씩 나열해 `netlify.toml` 을 만들었다.

`/*` 하나로 받는 방법도 있었다 — Netlify 는 force 안 붙인 규칙보다 실제 파일을 먼저 내주므로, 루트 사이트에 없는 주소만 writing 으로 흘려보낼 수 있다. 짧지만 오타 주소까지 넘어가고 루트가 자기 404 를 못 갖게 된다. 영구 리다이렉트 표는 정확한 편이 낫다고 보고 나열하는 쪽을 택했다.

생성 스크립트는 일회용이라 남기지 않았다. 글이 늘어도 이 표는 그대로면 된다 — 이사 시점의 주소만 받으면 되는 표라서.

### tech 와 ai 도메인은 루트 Netlify 사이트에 붙인다

둘 다 GitHub Pages 라 스스로 301 을 못 건다. 루트가 Netlify 로 가므로, 옛 도메인을 같은 Netlify 사이트에 붙이고 거기서 넘기기로 했다. `netlify.toml` 에 도메인을 통째로 적는 규칙(`from = "https://tech.sungd.uk/*"`)으로 처리한다.

### mermaid 다이어그램 하나

`tablet-dev-with-ngrok` 글에 mermaid 흐름도가 있는데 writing 사이트엔 렌더러가 없다. 글 하나 때문에 mermaid 의존성을 새로 넣는 건 과하다고 보고 글자 도식으로 바꿨다. 내용(흐름 두 갈래와 만나는 지점)은 그대로 담았다.

### 사이트끼리 잇는 링크를 컴포넌트로 (아래 Netlify 관련 서술은 뒤에 뒤집힘)

허브를 만드는 것보다 각 사이트가 서로를 가리키는 게 먼저라고 정리했으니, 루트에 `SiteLinks` 컴포넌트를 두고 홈·About·푸터에서 같이 쓴다. 자기 자신은 목록에서 빠진다. writing 푸터에도 같은 세 링크를 손으로 넣었다 — repo 가 달라 컴포넌트를 공유할 수 없다.

## 2026-08-07 — 전제가 틀려서 되돌린 것

### 사이트가 Netlify 인 줄 알았는데 전부 GitHub Pages 였다

리다이렉트를 `netlify.toml` 로 짜고 루트를 Netlify 로 옮기는 계획까지 세웠는데, 실제로 확인해보니 네 사이트 다 GitHub Pages 였다. `sungd.uk` 의 A 레코드가 GitHub Pages IP(185.199.108~111.153)였고, blog-writing 은 워크플로가 `dist/` 를 Pages 에 올리고 있었다.

blog-writing repo 에 `netlify.toml` 과 netlify 어댑터가 있어서 Netlify 라고 넘겨짚은 게 원인이다. 안 쓰는 잔재였다. **코드를 보고 배포처를 짐작하지 말고 DNS 와 응답 헤더를 봤어야 했다.**

### 넘김은 Cloudflare 가 맡는다

DNS 가 Cloudflare 라(`*.ns.cloudflare.com`) 호스팅을 안 건드리고 넘김만 얹을 수 있다. GitHub Pages 는 301 을 못 걸고 repo 하나에 도메인 하나뿐이라 tech·ai 를 자기 자리에서 넘길 방법이 없는데, Cloudflare 는 그 셋을 한 곳에서 처리한다. 그래서 `netlify.toml` 을 지우고 Pages 배포 워크플로를 되살렸다.

### 79편을 나열하는 대신 조건을 뒤집었다

Netlify 안에서는 글 주소 79개를 하나씩 적었다. Cloudflare 규칙은 개수 제한이 빡빡해서 같은 방식이 안 맞는다. 대신 "루트 사이트가 쓰는 주소가 아니면 옛 글" 로 뒤집어 규칙 하나로 줄였다. 루트가 쓰는 최상위 경로가 여덟 개뿐이라 가능한 방식이다.

대가는 두 가지다. 루트가 자기 404 를 못 갖고(모르는 주소는 writing 으로 간다), 루트에 새 최상위 경로를 만들면 규칙의 제외 목록에 추가해야 한다. 둘 다 `cloudflare.md` 에 적어뒀다.

### 그 밖

작업 도중 `~/dev/sites/` 가 없어지고 그 안의 폴더들이 `~/dev/` 바로 아래로 올라갔다. 이 세션이 한 일은 아니다. 작업본(worktree)이 절대 경로를 기억해서 끊겼고 `git worktree repair` 로 살렸다. 커밋은 이미 push 해둬서 잃은 건 없다. 이 문서의 경로는 옮긴 뒤 기준.

## 2026-08-09 — today 를 ai 로 되돌림

사용자 결정으로 `today.sungd.uk` 를 원래 이름 `ai.sungd.uk` 로 되돌렸다.

개명 근거(범위가 넓은 ai 보다 하는 일과 맞는 today)는 그때 판단 그대로지만, 실제로 써보니 사용자가 원래 이름을 택했다. today 가 살아 있던 기간이 하루도 안 돼 밖에 걸린 링크가 없고, `ai.sungd.uk` 는 그 사이 주인이 없어 404 였을 뿐이라 되돌리는 비용이 거의 없었다.

`plan.md`·`plan.html` 은 그때의 계획 기록이라 today 로 남겨둔다. 실제로 쓰는 `cloudflare.md` 와 `status.sh` 만 ai 로 고쳤다.
